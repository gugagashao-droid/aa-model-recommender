# 场景化反问库(需求细化)

本文件定义如何把用户的需求问细。目标:在给出模型推荐前,通过反问把"要做什么"细化到足以精确匹配 AA 子榜的程度。核心原则——**宽泛任务先问清场景背景,再由背景决定拆解方式和子榜选择**;原子任务只问影响选型的关键缺口。

## 一、反问的两类问题(都要覆盖)

1. **场景细化问题**:决定"任务怎么拆、看哪些子榜、领域归哪类"。这是本文件的重点,按场景不同而异。
2. **选型约束问题**(通用,每个任务都要问):执行方式(agentic/一次性/长输入)、优先级(效果/成本/速度)、部署约束(闭源/开源/国内可访问)。见 SKILL.md Step 2 的四问。

## 二、反问执行规范

- **集中成批**:每批最多 4 个问题,每题 2–5 个明确选项(另附"其他/你来定"),不要挤牙膏式一问一答。
- **最多两批**:宽泛任务第 1 批放最影响拆解的场景问题(≤4 题),第 2 批放优先级、部署约束和剩余场景问题(≤4 题);之后必须进入推荐,不得无限追问。原子任务一批问完。
- **给默认值**:每题提供可快速回答的选项;用户说"随便/你来定/按常规",就按最常见情况假设并在输出中写明假设。
- **按需追问**:只问会真正改变推荐结果的问题。已有信息不重复问;原子任务跳过无关的场景问题;下面场景库里问题超过 8 个时,挑最影响推荐的 8 个,其余用默认假设。

## 三、按场景的问题库

### 写论文 / 学术写作(宽泛任务)

必须问清(决定领域榜与模块裁剪):
- **学历/阶段**:本科课程论文 / 硕士学位论文 / 博士论文 / 期刊会议投稿 → 决定深度与模块复杂度。
- **专业/学科**:理科(数理化)/ 工科 / 医学 / 经管 / 法律 / 人文社科 → 映射到领域榜(物理 `aa_critpt`、医学 `aa_healthbench_professional`、法律 `aa_harvey_lab`、科学 `aa_gpqa`、经管 Capability Indexes)。
- **研究方向/题目**:让用户给出具体方向或题目;越具体越好,决定推理类子榜与领域榜。
- **论文类型**:综述 / 实证研究 / 理论推导 / 实验报告 → 决定文献综述、实验代码、推理模块权重。
- **语言与目标**:中文/英文、期刊格式要求 → 中文写作看 LM Arena 中文类别;英文写作看 LM Arena 创意写作类别和 aiwritingbenchmark(它没有中文版);格式要求影响 `aa_ifbench` 格式遵循。
- **数据/实验**:是否需要真实实验与数据分析 → 决定是否启用 `aa_analyst_agent`、`aa_scicode` 模块。

示例问法(分两批):
- 第 1 批:"写论文我先确认四件事:①你现在是本科/硕士/博士还是投稿?②专业方向是什么?③是综述、实证还是理论类?④需要真实实验数据吗?"
- 第 2 批:"再确认:⑤中文还是英文、有没有目标期刊格式?⑥更看重效果、成本还是速度?⑦对模型有没有部署限制(必须开源/必须国内可访问)?"
- 语言与格式如果用户已经说了,第 5 题就不用再问。

### 做网页 / Web 应用(宽泛任务)

必须问清:
- **网站类型**:静态展示/落地页 / 电商 / 后台管理系统 / SaaS 应用 / 博客 CMS → 决定是否需要后端、架构、运维模块。
- **技术栈偏好**:React/Vue/纯 HTML,有无指定框架或语言 → 影响 coding 榜的具体配置。
- **范围**:只做前端还是要含后端与数据库 → 决定模块裁剪。
- **设计诉求**:是否要高审美/原创视觉/图片素材 → 高审美启用"UI 审美与页面实现"模块(Contra Frontier Design),需要原创图片素材才另加"配图素材"模块(Image Arena)。
- **规模与部署**:个人 demo 还是生产环境、是否要上线运维 → 决定运维/SRE 模块权重(`aa_itbench_sre`)。
- **是否需要评审/团队协作**:是否强调代码质量与 review → 强化 review 模块(用户强调的"后端要看 review、架构")。

### 做 App / 移动应用

平台(iOS/Android/跨端)、原生还是混合、是否需要后端、是否要设计、上线与否、团队 review 需求。

### 数据分析 / 报表

数据来源与规模、分析目标(描述/预测/归因)、产出形式(报告/仪表盘/模型)、领域、是否需要可视化出图。

### 其他/原子任务

只问影响选型的缺口:输出形式、长度、是否有格式/合规要求、时效要求。**写作类任务必问语言**(中文还是英文,决定看哪张写作榜)。信息已够则直接推荐。

## 四、反问结果如何驱动后续

- 每一个 answered 场景问题都要落到具体动作:裁剪/增加某个叶子模块、换用某个领域榜、调整优先级加权、改变模型候选池。
- 在最终输出中简要复述"根据你的回答(学历/专业/类型…)",让用户看到反问被采纳,而不是走过场。
- 领域类回答(专业、行业)优先查 `aa-benchmarks.md` 的领域榜与官方 Capability Indexes,不要一律用通用 Intelligence Index。
