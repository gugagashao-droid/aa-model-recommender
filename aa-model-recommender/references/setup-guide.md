# 联网抓取依赖配置与环境检查

本技能只依赖"联网抓取"能力,全部访问公开榜单页面。不需要账号登录、API Key、Token 或 OAuth,没有凭据需要存储、轮换或撤销。

- **依赖标识**:`aa-data-sources`(类型 network,必需,无认证)。清单与降级映射见 `skill-dependencies.json`。

## 一、联网抓取能力

- **用途**:打开 AA 子榜页面读表格文本、按关键词搜索定位榜单与交叉验证。支撑"实时抓取AA榜单""联网搜索补充榜单"两项功能。
- **支持版本**:需要当前 harness 提供网页抓取(打开 URL)与联网搜索(关键词检索)两种工具;本技能用 harness 自带工具,不绑定具体产品名。
- **官方主页**:https://artificialanalysis.ai
- **官方文档**:https://artificialanalysis.ai/about
- **榜单数据页**:https://artificialanalysis.ai/leaderboards/models
- **登录网址**:不需要(全部为公开数据)
- **Token/Key/OAuth 入口**:不需要
- **登录后路径**:不适用
- **权限与 scope**:不适用,只读访问公开页面
- **配置步骤**:
  1. 确认 harness 已启用网页抓取与联网搜索工具;例如 WebFetch / WebSearch,其他环境用等价工具即可。
  2. 确认可访问 artificialanalysis.ai 官方站,以及 benchleader.com、modelcap.ai 等聚合站;任一可达即可抓取,多源互为备份(数据源优先级见 `fetch-guide.md` 第一节)。外部榜与镜像涉及的站点还有:contralabs.com、aiwritingbenchmark.com、aitntnews.com、raw.githubusercontent.com。官方页带人机验证或在你的网络下连不上时,技能会请你在自己的浏览器里打开页面并贴出表格或截图。
  3. 运行只读检查器确认运行时环境(命令见下);检查器不探测榜单站点可达性。
  4. (可选)harness 的抓取工具连不上榜单站点时,技能会改用 `scripts/fetch_page_text.py` 在你的本机读取页面。它自动沿用你已有的系统代理或环境变量代理(Windows 读注册表里的系统代理),**不修改任何代理或网络设置**。你的浏览器能打开、抓取工具却连不上时,这一档通常能解决。
- **凭据存储**:不适用(无凭据)。
- **验证方式**:`python -X utf8 <技能根目录>/scripts/check_environment.py --capability 实时抓取AA榜单 --capability 联网搜索补充榜单`(用绝对路径;Windows 没有 `python` 时改用 `py -3 -X utf8`),返回 ready/partial/needs_setup/unavailable。清单只声明 Python 运行时检查,不带 url 探测项,故检查器不访问任何外网。
- **过期、权限、额度处理**:无账号与额度概念;若某站返回 401/403/429,按 `fetch-guide.md` 第一节换源,不重试到无限。
- **轮换和撤销**:不适用。
- **核验日期**:2026-11-22
- **适用版本**:1.1.0

## 二、环境检查

进入推荐前按 `SKILL.md` Step 0 运行检查器。检查只确认本地运行时(Python 版本),**不探测榜单站点的网络可达性**——榜单站在不同用户环境里可能只经本机代理或只在平台出口可达,本地脚本探测境外站会误判(典型:用户未配代理时探测超时报 `partial`,但平台抓取工具实际能抓到榜)。检查不抓榜、不修改配置、不输出任何凭据值。

四种状态与路由:

| 状态 | 含义 | 下一步 |
|---|---|---|
| ready | 本地运行时就绪(Python 满足) | 跳过引导,直接 Step 1;能否抓榜以 Step 4 实际抓取为准 |
| partial | 可选检查项未就绪 | 继续 Step 1;本技能清单当前无可选检查项,基本不会出现 |
| needs_setup | 缺少必需能力(如无 Python 且无等价静态判断) | 只展示缺失项与配置入口,完成后重检 |
| unavailable | 本地运行时故障 | 给恢复步骤与降级,按 `fetch-guide.md` 第四节处理 |

**联网可达性的判断完全交给实际抓取**:Step 4 抓得到就用、抓不到按 `fetch-guide.md` 第四节换源/降级,不依据预检结果提前降级,也不因预检"看起来能连"就假定一定能抓到。

无法运行脚本时(harness 禁止子进程或无 Python):做静态判断,确认具备"打开 URL 读文本"与"关键词搜索"两种能力后继续;缺一时按降级矩阵处理并标注"未验证"。已完成的配置不重复引导。

## 三、功能降级矩阵

| 功能 | 失败条件 | 降级方式 | 用户补充 | 限制与证据标签 | 恢复方式 | 停止条件 |
|---|---|---|---|---|---|---|
| 实时抓取AA榜单 | 抓取工具不可用或全部源不可达 | 换源重试;仍失败给定性保守建议,不指定精确 Top3 | 可粘贴榜单文本 | 无实时数据不冒充排名,标注未验证 | 网络/工具恢复后重跑检查并抓取 | 要求实时精确排名且无可信数据时停止 |
| 联网搜索补充榜单 | 搜索工具不可用或外部榜无结果 | 退回自检 SKILL 清单;无合格榜按置信度门槛处理 | 可提供候选榜名称/链接 | 低置信榜不进 Top3,单一来源需标注 | 搜索恢复后重走情形 B 分级 | 无达标榜时如实告知,不拼凑 Top3 |
| 逐模块排序推荐 | 分数/价格/速度字段不完整 | 只用有证据字段排序,缺失填 — | 无需 | 精度下降,标注缺口,部分验证 | 字段补齐后重排 | 关键分数字段缺失无法排序时停止该模块 |
| 输出格式与可靠性标注 | 降级或低置信来源进入结果 | 按 `output-format.md` 第六节披露降级级别、置信度与局限 | 无需 | 结果带限制标注,部分验证 | 来源恢复置信后移除标注 | 无 |

## 四、静态预检说明

`scripts/check_environment.py` 来自包内依赖工具模板,为只读检查器:读 JSON 清单、可选做匿名 HTTPS HEAD 探测(仅 `--network` 开启时)、检查 Python 版本;不写文件、不启动子进程、不读取环境变量凭据、不做动态执行。基于通用依赖检查模板,v1.1.0 去掉了平台名称和写死的 MCP 配置目录(新增 `--mcp-config` 参数,本技能不用),检查逻辑未改动。

另一个脚本 `scripts/fetch_page_text.py` 不属于环境检查,它是真正会联网的只读读取器:仅允许 HTTPS 和脚本内的站点白名单(每次重定向都复查),只做 GET,不带 Cookie 和凭据,不写文件,只用 Python 标准库。它会读取系统或环境变量里已配置的代理地址,输出时只显示主机和端口,不显示代理账号密码。需要读取白名单以外的站点时,须先征得用户同意再修改脚本里的 `ALLOWED_HOSTS`。脚本本身仍保留 `--network` 探测能力(通用模板),但本技能的清单不声明任何 url 检查项,运行时不带 `--network`,也不会访问外网——技能使用方式由 `skill-dependencies.json` 决定,无需改动脚本。
