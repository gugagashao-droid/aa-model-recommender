# 基线对比：不带技能 vs 带技能

> **注意:本文件含 2026-11-22 的榜单数据快照,仅作演示。运行时不得把这里的名次、分数、价格当作实时排名引用,每次推荐必须重新抓取。** 本文件也不参与运行时加载。v1.1.0 起"审美/视觉设计"模块改用 Contra Frontier Design(见 `references/aa-benchmarks.md` 第五节),下文第二节表格中的旧写法保留为历史记录并已加注。

本文件记录一次"同一任务、两种模式"的定性基线对比，用于回答 `trigger-tests.md` 待补项第 4 条："带技能输出是否存在可观察增量"。

## 方法学定位（先说清楚边界）

- **不是严格 A/B 实验**：本环境无法开启隔离会话、也无法观察独立对话中技能是否被自动加载，因此不能把"带技能"记为真实自动加载后的输出。
- **基线是模拟的**：左栏"不带技能"是按"通用 agent 无本技能时的典型输出模式"写的示意回答，**不声称是某个具体模型的真实回复**；其中不给出任何看似精确的分数，以免被误读为实测数据。
- **带技能栏是真实抓取的**：右栏所用排名、分数、日期均来自本次联网实抓（见文末附录），可核验；流程严格按 `SKILL.md` 的 Step 0–5 与 `references/` 规范执行。
- **对比的是结构性差异**：结论只基于可观察的流程/产物差异（反问、拆解、子榜映射、实时数据、日期、去重、可靠性标注、降级披露），不依赖主观"谁答得更好"。

## 测试用例

采用正例 T01（见 `trigger-tests.md`）：**"我要做个网页，该用哪个模型？"**
理由：它是宽泛任务，最能体现本技能区别于通用回答的核心能力——拆解模块、逐模块映射子榜、逐模块实抓。

---

## 一、不带技能（模拟基线）

> 典型形态：直接把"做个网页"当开发请求，凭训练记忆给几个模型名，理由停留在"能力强/流行"，不反问、不拆模块、不查榜、不标日期。

"做网页的话，推荐用 Claude 或 GPT 这类前沿大模型，代码能力比较强；如果考虑性价比可以用 Gemini。具体看你预算，效果优先就选最贵的那档。"

**可观察特征**：
- 无反问，直接作答（不知道是静态站还是带后端、什么技术栈、要不要设计）
- 无任务拆解，一个"万能模型"回答全部
- 无子榜概念，理由空泛（"能力强""流行""最贵那档"）
- 无数据日期、无来源、无可核验依据
- 无变体去重、无证据等级、无可靠性标注
- 无降级/边界说明

## 二、带技能（本次实抓）

### 需求细化复述与反问
按 Step 2 先反问：网站类型（静态/动态/电商）、技术栈、是否含后端、设计诉求、规模与部署、是否要 review。用户若说"你来定"，按常规假设写明（此处假设：中等规模动态站、含前后端、重视视觉、效果优先）。

### 任务拆解总览（Step 3）

| 模块 | 核心能力 | 依据子榜 |
|---|---|---|
| 前端开发 | 仓库级代码改动 | `aa_frontiercode_20`、`aa_terminalbench_40` |
| 前端视觉还原 | 代码落地视觉 | `aa_frontiercode_20` |
| 审美/视觉设计 | 出图/审美 | 官方 Image Arena（本次未展开 Top3，见限制；v1.1.0 起改为 Contra Frontier Design，Image Arena 只负责配图素材） |
| 后端开发 | 服务/接口代码 | `aa_frontiercode_20`、`aa_automationbench` |
| 架构设计 | 综合判断 | `aa_intelligence_index_v5` |
| 代码 review | 合并判定/质量 | `aa_frontiercode_20` |
| 测试部署运维 | 终端/运维 agent | `aa_terminalbench_40`、`aa_itbench_sre`（本次未展开 Top3） |

### 跨模块综合建议（Step 5）

- **通用强模型**：Claude Fable 5.2 在编码榜与综合榜均排第一，可承担前后端开发、review、架构主线。
- **专用模块**：审美/视觉设计需单独看设计榜（v1.1.0 起为 Contra Frontier Design；旧写法"换 Image Arena 出图模型"有误，出图模型写不了页面代码）；测试运维按 Terminal-Bench/SRE 榜另选。
- **组合策略**：Fable 5.2 做主线 + 视觉设计模块换专用出图模型；成本敏感时把开发/review 换成 Claude Opus 5.5(max)（编码 46.4% 但价格约半）。
- **取舍**：本次为效果优先；若成本优先，按"分数÷输出价"重排会偏向 Gemini 4 Carbon（60.0÷10≈6.0）和 Gemini 4 Neon（61.4÷15≈4.1），Claude Opus 5.5（59.1÷20≈3.0）次之，Fable 5.2 与 Astra 约 1.6。这里只按输出价粗估，未计输入价与思考 token。

### 可靠性标注
- 数据日期：编码榜 22 Nov 2026（源结果 9 Nov）、综合榜 21 Nov 2026，距抓取当日 <60 天，不算旧。
- 来源：benchleader.com、modelcap.ai 公开榜，均为 Artificial Analysis 独立测评的聚合，非厂商自报。
- 排名只反映所测子榜，不等于真实生产表现；建议在自己的任务上小样本验证。
- 视觉设计、测试运维两模块本次未抓完整 Top3，按输出规范只给映射与首选方向，未编造名次。

## 三、逐维度对比

| 维度 | 不带技能（模拟基线） | 带技能（本次实测） | 可观察增量 |
|---|---|---|---|
| 意图识别 | 当开发任务直接答 | 识别为"模型选型 + 宽泛任务" | 有 |
| 反问澄清 | 无 | 通用四问 + 场景深挖，最多两轮 | 有 |
| 任务拆解 | 无，一个模型通吃 | 拆 7 个叶子模块 | 有 |
| 子榜映射 | 无 | 每模块映射到具体 slug | 有 |
| 实时数据 | 凭记忆，无日期 | 现场抓两个榜，带数据日期 | 有 |
| 可核验性 | 无来源、无名次分数 | 真实名次/分数 + 来源 URL | 有 |
| 变体去重 | 不会 | Fable/Astra 多变体合并为一条 | 有 |
| 可靠性标注 | 无 | 数据日期、证据等级、局限提示 | 有 |
| 降级/边界 | 无概念 | 三级降级、不编造 Top3 | 有（本次未触发，属流程约束） |
| 输出结构 | 一段话 | 多模块版式 + 跨模块综合建议 | 有 |

## 四、结论

在 T01 上，带技能输出相对基线在 **9 个可观察维度上都有增量**，其中最硬的三项是：**实时抓取＋数据日期**（基线完全不具备）、**逐模块拆榜与绑定真实名次**（基线只能空泛推荐）、**变体去重与可靠性披露**（基线不会做）。这证明技能的核心设计不是"换个说法"，而是改变了产出的信息含量与可核验性。

**必须保留的诚实边界**：本对比的基线是模拟的、不是隔离 A/B；"实际是否触发"仍未验证。要做严格结论，仍需在可观察技能加载的 harness 里用独立会话重跑 T01–T05 并保留触发证据。
